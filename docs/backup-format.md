# Portfolio backup format

The supported investment export uses `format: "meu-portfolio-backup"`, version 5,
`exportedAt` and `tables`. The format identifier and field/table keys are historical
contracts and must not be translated. English UI labels do not rename stored taxonomy.

Version-5 table order:

`dataImports`, `institutions`, `accounts`, `assets`, `portfolioMonths`, `positions`,
`positionAllocations`, `positionTransactions`, `targetPlans`, `allocationTargets`,
`manualQuotes`, `marketQuotes`, `dailyQuotes`.

User-scoped rows omit their owner ID. Restore binds them to the authenticated user.
Dates are ISO strings, decimals remain strings and supported BigInts are converted
explicitly. References are restored in dependency order; conflicting IDs are remapped
with their foreign keys. Shared quotes are added only when missing.

Users, passwords, sessions, quote-run logs, derived symbol registrations, CDI coverage
and Selic history are not included. Public reference rates are regenerated by the job.
Historical generated transaction notes may remain Portuguese in stored data; the UI
recognizes/translates their markers while preserving free-form user notes.

The UI offers export and a two-step import: validate/check, then explicitly confirm
apply. Apply replaces the target user's portfolio tables transactionally. Never use
restore merely to test a feature against real data. Use an isolated development schema.
Keep the original export and a backup before any production restore.

```sh
pnpm backup:export --user user@example.com
pnpm backup:restore --user user@example.com backups/file.json
pnpm backup:restore --user user@example.com backups/file.json --apply
```

Changing the data model requires updating table specs, reference mappings, validation,
upgrade paths and compatibility tests before increasing the format version. Existing
exports must continue restoring. Financial JSON exports remain outside Git.

Legacy family/income backup formats and database tables are retained historically;
their application screens and routes are retired from the investment-only workspace.


`assets.fixedIncomeContract` is optional nullable JSON in version 5. Older backups
without it continue to restore. It retains the Brazilian bank-deposit product,
issuer, indexer, contracted rate and interest basis. The shared monthly IPCA
observations are regenerated, like CDI; they are not private backup data.

The optional assets.fixedIncomeContract JSON also accepts the tagged
`type: international-bond` document: issuer, identifier, denomination, original
acquisition cost/face amount and private dated full-value observations. Actual
coupons and principal receipts remain position transactions. Preserve both to
restore valuation and realized/unrealized gains. Existing backups without this
column continue to import. No version bump is required.

## Security boundary for web restores

Web restoration references existing shared market/daily quotes and never inserts client-supplied global prices. A backup with shared history missing from the destination server is rejected atomically; the administrator can first import a trusted archive using the CLI. Version-5 structure is unchanged. Web uploads are bounded to 10 MB (subject to hosting limits) and 100,000 rows per table.
